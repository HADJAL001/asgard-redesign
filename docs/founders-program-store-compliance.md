# Founders Program: копирайт и store-инвариант

Фаза 2 плана `clever-soaring-russell.md` (embeddable credential-бейдж, Фаза 1 —
`GET /certified/:serial/badge.svg` — приземлена в PR #119). Эта фаза — без кода,
чек-лист двух рисков модели «$990/мес + встреча с создателями + сертификат»,
которые нельзя закрыть кодом, только формулировкой и договорённостью на будущее.

## 1. Копирайт: «сертификация», не «лицензирование»

Слово «лицензирование» юридически заряжено (регуляторная лицензия — совсем
другая категория обязательств, чем экосистемный credential). Комментарий в
миграции `084_academy_certificates.ts` уже разводит эти понятия («НЕ лицензия,
бренд-сертификация экосистемы»).

**Проверено на 2026-07-26** (grep по `components/`, `app/`, `lib/i18n/locales/*.json`,
вне `marketing/launch-package/`): формулировка нигде не сползла на «license» /
«лицензирование» применительно к сертификату. Действующая точка правды —
`components/certified-registry-view.tsx:246`:

> «OSGARD Certified Vibecoder» — экосистемная сертификация платформы, а не
> государственная лицензия.

Это и есть требуемая рамка. Держать её при любых будущих правках user-facing
текста про Founders/Academy/сертификат (карточки `academy-view.tsx`,
`certified-credential.tsx`, README-сниппет бейджа, будущие email/лендинги):
**«verifiable credential» / «сертификация», никогда «license» / «лицензирование»**
вне `marketing/launch-package/` (тот контур не в этом домене).

## 2. Store-инвариант: mobile-чекаут, если Founders Program придёт в `mobile/`

**Текущее состояние (проверено 2026-07-26):** `mobile/` не содержит ни Stripe,
ни Founders/Academy-кода вообще — Founders Program существует только на вебе.
Это не случайность, а инвариант, который важно не сломать, когда/если
мобильный клиент дорастёт до продажи тира `founder_circle`.

**Правило на будущее (зафиксировать, не строить сейчас):** любой чекаут
Founders Program в `mobile/` обязан идти через `expo-web-browser` на
существующий веб-Stripe Checkout (тот же поток, что и на вебе), **не** через
нативную кнопку покупки/react-native-iap внутри приложения. Причина: цифровая
подписка, купленная нативной кнопкой в iOS/Android-приложении, подпадает под
обязательный IAP сторов (Apple/Google берут комиссию и требуют собственный
платёжный флоу) — обход через внешний браузер для уже существующего
веб-Stripe-чекаута такому требованию не подчиняется, это стандартный и
принятый паттерн (по аналогии с тем, как это делают другие продукты с
веб-биллингом).

Если кто-то в будущем начнёт добавлять Founders/Academy/Stripe в `mobile/` —
это первое, что нужно перепроверить, прежде чем открывать PR.
