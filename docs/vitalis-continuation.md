## 1. Что такое VITALIS

AI-коуч здорового долголетия для рынка ЕС (Германия, Франция, Великобритания; 25–55 лет).
Пользователь фотографирует еду → получает калории, БЖУ и оценку пользы для долголетия 0–100;
ведёт дневник, видит дашборд и рекомендации.

Бизнес-модель, поставленная основателем:

| Поток | Цена |
|---|---|
| Premium-подписка | 39 €/мес (390 €/год) |
| Pay-per-use (разовый анализ) | 4,99 € |
| Партнёрский маркетинг | % с продаж партнёров |

Ограничения MVP: бюджет 15 000 $, срок 14 дней, команда — архитектор + 2 разработчика +
1 маркетолог. Целевая конверсия в подписку > 5 %. Требование основателя: **доход с первого дня**.

## 4. Чего нет — и почему это блокирует деньги

| Пробел | Следствие | Кто должен закрыть |
|---|---|---|
| Ни одного вызова Claude API — анализ фото макет | продукта фактически нет, только витрина | руками (движок не подключает внешние AI-ключи) |
| Stripe отсутствует; `app/api/` — 0 роутов | **кнопка «Оформить Premium» не делает ничего** → 0 € выручки | руками |
| Нет схемы PostgreSQL | нечем хранить пользователей, дневник, подписки | руками |
| Нет интеграций Apple Health / Google Fit | обещанная биометрия недоступна | руками |
| Сгенерирован веб (Next.js), а не React Native | нет мобильного приложения, а именно оно шло в App Store / Google Play | руками либо новой генерацией |
| 20 нерешённых `prop-unknown` | часть экранов может отрисоваться пусто | движком («Починить»), но он не сходится |

Итого: витрина — примерно 40 % MVP. Монетизация — 0 %.

## 5. План следующего окна

Порядок выбран так, чтобы деньги появились как можно раньше.

1. **Схема PostgreSQL** — `users`, `meals` (фото, калории, БЖУ, longevity_score),
   `daily_totals`, `subscriptions`, `payments`, `usage_counters` (лимит 3 анализа в день),
   `affiliates`. Миграции + индексы под запросы дашборда.
2. **Оживить оплату (первый приоритет по деньгам)** — Stripe Checkout по схеме
   web-to-app: покупка совершается в браузере (в обход 30 % комиссии магазинов), приложение
   узнаёт о подписке через вебхук и `subscriptions`. Кнопка «Оформить Premium» обязана вести
   на реальную оплату. Полезные готовые документы репозитория: `docs/stripe-live-checklist.md`.
3. **AI-ядро** — роут анализа фото на Claude API: изображение → калории, БЖУ, оценка
   долголетия 0–100 и короткое объяснение. Строгая схема ответа, кэш по хешу изображения,
   лимит на Free-тарифе.
4. **Онбординг «free → paid за 7 дней»** — 3 бесплатных анализа, на третьем — мягкий
   пейволл с личной выгодой; письмо на 2-й и 5-й день; скидка на годовой тариф на 6-й.
5. **Мобильное приложение** — React Native/Expo с паритетом веба (обязательное требование
   основателя: любая фича есть на обеих платформах).
6. **Маркетинговые гипотезы для первых 1000 платящих** — TikTok-инфлюенсеры в нише
   здоровья (DE/FR/UK), ASO под «longevity», «health coach», «AI nutrition», партнёрская
   программа с процентом.

Правило работы: то, что умеет платформа, делать **платформой** («Починить», «Доработать
словами», «Задеплоить»); руками — только принципиально недоступное движку (внешние ключи,
платежи, бэкенд). Молча подменять генератор ручным кодом запрещено.

## 7. Дефекты самой платформы, замеченные на этом проекте

1. Деплой падал на `useSearchParams` без `Suspense` — ни одна из проверок движка этот класс
   не ловит: настоящий `next build` в проде не запускается.
2. Починка свойств не сходится: 20 `prop-unknown` остаются, модель правит вызов, а не
   приводит его к сигнатуре.
3. Живой запуск в браузере недоступен — нужна кросс-origin изоляция страницы.
4. Индикатор этапов сборки декоративен: API отдаёт только статус `generating`, а полоса
   этапов — анимация, не отражающая реальную фазу. Счётчик «Расход» при этом честный:
   на доработке он показал 79 обращений к моделям и ≈499 тыс. токенов за 2 мин 15 с.
5. Название и описание проекта перезаписываются текстом доработки — карточка VITALIS
   называется «проект в направлении „Оберни useSearchParams…“».
6. Движок не подключает внешние AI-ключи и платежи — то есть не может довести приложение до
   выручки без ручного кода.
