# Подключение ЮKassa (оплата подписки из России)

Оплата картами РФ (Мир/Visa/MC), СБП, SberPay для тарифов `pro`/`supreme`/`duo`/`elite`.
Работает параллельно со Stripe: на странице `/pricing` под кнопкой Stripe есть
вторая кнопка **«Оплатить из России (ЮKassa)»**.

Разовый платёж активирует план на **30 дней**. Автопродление пока не реализовано —
по истечении месяца пользователь оплачивает снова.

---

## 0. Что уже готово в коде (трогать не нужно)

| Слой | Файл | Что делает |
|---|---|---|
| Конфиг | `backend/src/lib/yookassa.ts` | Клиент API, цены планов в ₽ |
| Роуты | `backend/src/routes/yookassa.routes.ts` | `POST /yookassa/create-payment`, `POST /yookassa/webhook` |
| БД | `backend/src/migrations/068_yookassa_payments.ts` | Таблица идемпотентности (создаётся сама при старте) |
| Фронт | `components/pricing-view.tsx` | Кнопка «Оплатить из России (ЮKassa)» |

Без ключей провайдер выключен: `create-payment` отдаёт `503`, ничего не ломается.

## 1. Зарегистрировать магазин в ЮKassa

1. Перейти на <https://yookassa.ru> → **Подключить ЮKassa**.
2. Для **боевого** режима нужен ИП / ООО / самозанятость (ЮKassa проверяет реквизиты).
3. Для **теста** сразу доступен тестовый магазин — регистрация юрлица не требуется,
   можно проверить весь поток на тестовых картах. **Рекомендую начать с теста.**

---

## 2. Получить shopId и секретный ключ

В личном кабинете ЮKassa:

1. **Настройки → Магазин** → скопировать **shopId** (число).
2. **Настройки → API-ключи** → выпустить **секретный ключ**:
   - тестовый начинается с `test_...`
   - боевой начинается с `live_...`

---

## 3. Вписать ключи в `backend/.env`

Файл уже подготовлен — осталось вставить значения (плейсхолдеры добавлены в конец):

```env
YOOKASSA_SHOP_ID=123456
YOOKASSA_SECRET_KEY=test_XXXXXXXXXXXXXXXXXXXXXXXX
```

(Необязательно) переопределить рублёвые цены — иначе используются дефолты
pro 2900 / supreme 9900 / duo 14900 / elite 19900 ₽/мес:

```env
YOOKASSA_PRICE_PRO=2900
YOOKASSA_PRICE_SUPREME=9900
```

Перезапустить backend (`cd backend && npm run dev`). В логах на старте не должно
быть предупреждений про ЮKassa — значит ключи подхвачены.

---

## 4. Настроить webhook (уведомление об оплате)

Подписка активируется **только после** уведомления `payment.succeeded` от ЮKassa —
поэтому webhook обязателен.

1. В ЛК ЮKassa: **Настройки → HTTP-уведомления**.
2. Указать URL: `<публичный адрес backend>/yookassa/webhook`
   - в проде это `BACKEND_PUBLIC_URL` из `.env`, например
     `https://your-service.up.railway.app/yookassa/webhook`
   - **локально** ЮKassa не достучится до `localhost` — подними туннель, например
     `ngrok http 3002`, и укажи выданный `https://…ngrok…/yookassa/webhook`
3. Отметить событие **`payment.succeeded`** (остальные можно не включать —
   наш обработчик их игнорирует и отвечает `200`).

Проверка безопасности уже встроена: ЮKassa не подписывает уведомления, поэтому
сервер **не доверяет телу**, а перезапрашивает платёж по `id` через API и
активирует подписку только при authoritative-статусе `succeeded`. Повторная
доставка того же платежа не задвоит подписку (идемпотентность в `yookassa_payments`).

---

## 5. Проверить оплату (тестовый режим)

1. Зайти на `/pricing` авторизованным пользователем.
2. Нажать **«Оплатить из России (ЮKassa)»** на любом платном тарифе.
3. Откроется страница оплаты ЮKassa → ввести **тестовую карту**:
   `5555 5555 5555 4444`, любой срок в будущем, любой CVC.
   (Полный список тестовых карт: <https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing>)
4. После оплаты произойдёт редирект на `/wallet?checkout=success&plan=…&provider=yookassa`.
5. Придёт webhook → в БД `subscriptions.plan` станет выбранным, `status='active'`,
   в `transactions` появится запись с `currency='rub'`. Проверить можно на `/wallet`.

---

## 6. Боевой режим (выбран как основной)

1. Пройти проверку реквизитов в ЮKassa (ИП/ООО/самозанятость) и активировать магазин.
2. В `backend/.env`:
   - `YOOKASSA_SECRET_KEY` = боевой ключ (`live_...`)
   - `YOOKASSA_SHOP_ID` = боевой shopId
   - `NODE_ENV=production`
   - `BACKEND_PUBLIC_URL` = боевой HTTPS-адрес backend
3. Webhook в ЛК → на боевой `<BACKEND_PUBLIC_URL>/yookassa/webhook`, событие `payment.succeeded`.
4. Провести один реальный платёж на минимальном тарифе (`pro`, 2900 ₽) для контроля,
   затем оформить возврат через ЛК ЮKassa.

> **Защита встроена:** если в `NODE_ENV=production` подставить тестовый ключ
> (`test_...`), backend не стартует и укажет на ошибку — боевой трафик не уйдёт
> в тестовый магазин по недосмотру.

### ⚠️ 54-ФЗ / онлайн-касса (важно для боевого режима)

Если у магазина в ЮKassa **подключена онлайн-касса** (для большинства ИП/ООО это
обязательно по 54-ФЗ), ЮKassa **отклонит платёж без чека**. Код это уже
поддерживает:

- В платёж автоматически передаётся `receipt` с **email покупателя** (берётся из
  профиля пользователя) и позицией «подписка».
- Ставка НДС задаётся `YOOKASSA_VAT_CODE` в `.env` (по умолчанию `1` = без НДС,
  подходит для самозанятых/УСН; для ОСН с НДС 20% поставь `4`).
- Если у пользователя **нет email** в профиле — чек не передаётся. Для магазина
  с кассой такой платёж не пройдёт, поэтому убедись, что email собирается при
  регистрации, либо добавь запрос email перед оплатой.

Если онлайн-кассы у магазина нет (напр. часть самозанятых) — чек не нужен, всё
работает и без email.

---

## Ограничения (осознанные, на будущее)

- **Автопродление** не делается — платёж разовый на 30 дней. Рекуррентные списания
  ЮKassa (сохранённый способ оплаты) — отдельный тикет.
- **Смена тарифа/возвраты** через ЮKassa не автоматизированы (Stripe-специфичный
  `change-plan` их не покрывает).
- Валюта платежа — только **RUB**.
