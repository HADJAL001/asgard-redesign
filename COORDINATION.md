2. **Порядок мержа при гонке:** если оба готовы влить пересекающиеся правки — первым

3. **Разбитие дедлока:** «ничейную» или обоюдно-уступленную задачу A закрепляет за

Это **не** «важнее»: **Claude B полновластен в своём домене** (монетизация,
маркетплейс, аукционы, генерация/Кузница, real-time) — там A не арбитрствует, а
согласовывает. Если B возражает против самого старшинства — пишет в «Диалоге»
`B: возражаю — <довод>`, до разрешения действует текущий протокол.

**Правило передачи задачи (лечит баг «оба сняли growth-ридер»):** снимать свою
реализацию ничейной задачи можно **только одновременно** с записью
`ПЕРЕДАЮ <задача> → <имя>`, и получатель **обязан подтвердить** `ПРИНЯЛ <задача>`.
Нет подтверждения — **не снимай свой код**, иначе задача проваливается в дыру (как
только что growth-ридер: B снял growthFunnel «оставив за A», A снял `growth` «оставив
за B» → на `main` ридера нет ни у кого).

## Правила (обязательные)

1. **Никогда не коммить прямо в `main`.** Только feature-ветка → PR → squash-merge.
2. **Перед началом:** `git fetch origin main && git rebase origin/main` на своей ветке.
   Это ловит конфликты рано, а не при мерже.
3. **Миграции — главный источник коллизий.** Перед созданием:
   - `git fetch origin main`, посмотреть максимальный номер в `backend/src/migrations/`;
   - взять **следующий свободный** номер;
   - **сразу вписать его в «Занятые номера миграций» ниже**, чтобы второй не взял тот же.
4. **Общие файлы** (`auth.controller.ts`, `server.ts`, `lib/auth-store.tsx`, `db.ts`) —
   правь только точечно и объяви в статусе, что их трогаешь. Не переписывай целиком.
5. **Мелкие частые коммиты** и быстрый мерж — чем дольше живёт ветка, тем больше
   расхождение. Не копи большие диффы.
6. **После мержа** — обнови статус (задача → done) и, если менял общий файл, напиши это.
7. **🔴 ОБЩИЙ РАБОЧИЙ КАТАЛОГ (пока не развели по клонам):** НИКОГДА `git add -A` и
   никогда `git add <общий-файл>` целиком. Только `git add -p` или свои файлы поимённо.
   ВСЕГДА `git diff --cached --name-only` перед `git commit` — если видишь чужой файл,
   ты его случайно захватил (см. инцидент выше про сломанный build). Атомарность:
   фичу коммить целиком (обвязка + все её новые файлы вместе), иначе ломаешь сборку.
